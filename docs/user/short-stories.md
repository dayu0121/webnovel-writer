# 番茄短故事工作台使用指南

本项目的短故事模式只服务番茄短故事。既有长篇书仓仍可读取和兼容，但新建短故事不能选择其他平台或通用规则包。

## 新建

告诉工作台：“新建一篇番茄短故事，题目是《不存在的二十三楼》，目标超短篇，核心钩子是……”主控会固定使用 `fanqie-short-story@1` 规则包，整理作品卡和一页故事蓝图，展示两份 hash 后请求确认。作者确认后才允许起草整篇。

规则包的来源、版本、hash、公开篇幅口径和活动边界见：[番茄短故事规则包 v1](fanqie-rule-pack-v1.md)。

此前预览版中未绑定番茄规则包的短故事 manifest 会被拒绝读取；本预览版不自动猜测或迁移其平台身份。

## 推进

短故事只有两个常规作者门：

1. 故事卡与蓝图确认。
2. 最终正文、审读记录、交付检查和规则包 hash 确认。

两次确认之间，起草、全篇审读、发现项处置、改稿和交付检查可以连续推进。遇到重大改向、作者保留意见、hash 冲突或工具失败会停下。

## 审读与交付

全篇审读固定为结构与因果、人物与情绪、连续性与交付三个模块。改文后旧审读自动过期，必须重审。交付检查绑定当前正文、计划、审读和 `fanqie-short-story@1` 规则包 hash。

超短篇和中短篇的公开字数口径会参与目标归一化；活动专属投稿字段、奖励口径和题材限制不自动硬编码。检查结果区分阻断和提醒，不能替代番茄后台审核。

## 导出

作者指定绝对目录并批准后，工作台写入：

- `<故事名>-定稿.md`
- `<故事名>-定稿.txt`

导出不含卷号或章号；已有不同内容时拒绝覆盖，写后逐文件读回校验。投稿、邮箱发送与番茄平台发布仍由作者手工完成。
