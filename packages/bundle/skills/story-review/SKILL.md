# 短故事审读

审读对象是一篇完整待审稿，不按卷章判断。三个模块必须分别回写；无发现项也要回写空数组。

## 模块一：结构与因果

核对开篇钩子、核心冲突是否具体、升级节点是否有因果推动、主角是否主动选择、关键转折是否有前文依据、高潮与高潮、结局是否回收承诺。检查支线是否稀释主线、解释是否替代行动、反转是否只靠巧合或新信息硬塞。

## 模块二：人物与情绪

核对人物欲望、底线、行动力和关系变化是否前后一致；金手指或外部帮助是否只提供信息/阻力，没有替主角代打；情绪是否由事件和选择产生；高潮释放是否与前文蓄势匹配；结尾是否留下必要余味而非突然拔高。

## 模块三：连续性与交付

核对人物称谓、时空、物件、规则、信息边界和因果时序；清理 TODO、待补、重复段落、机械套话和视角漂移。篇幅对照本故事 `故事.json` 的目标区间和 `fanqie-short-story@1` 规则包：偏离给提醒，不把活动规则凭空套成永久硬阈值。短剧/漫剧延展性只作创作建议，不作合规判定。

## 发现项格式

每个发现项必须含：

```json
{
  "发现项编号": "结构与因果-1",
  "证据位置": "正文中的可定位句或段落",
  "问题说明": "具体后果，不写空泛评价",
  "修改建议": "最小可执行修改",
  "影响范围": "开篇/中段/高潮/结局/连续性"
}
```

要求：

- 证据必须来自本次待审稿；不引用旧稿或想象内容。
- 一个问题只写一个发现项；同根因可合并。
- 软偏好不伪装成硬错误；篇幅偏离通常是提醒。
- 不输出重写整篇，不代替作者决定是否接受。

## 回写与复审

主 Agent 先调 `story_review_identity` 取 `fingerprint`，每个模块单独调 `story_record_review`。正文或计划变化后旧 fingerprint 立即失效；改稿后所有模块重新审读。发现项处置完成且三个模块齐全，才可运行 `story_prepare_delivery`。
